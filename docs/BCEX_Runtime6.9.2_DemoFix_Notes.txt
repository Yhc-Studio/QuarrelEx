BCEX Runtime 6.9.2 - Demo auto-fire isolation fix
==================================================

Observed symptom
----------------
The Demo still consistently drives/fires into the HQ even after the
Runtime 6.9.1 Demo isolation changes.

Confirmed remaining cause
-------------------------
The original Demo AI itself was already intact.

At CPU $C6C2 it uses the input table:

  13 43 23 83

Each value contains:
- a direction in the high nibble,
- A + B in the low bits.

The original Demo AI has a specific HQ-side safety behavior:

  $C6B1  LDA player Y
  $C6B3  CMP #$C8
  ...
  $C6B7  LDA ram_btn_press,X
  $C6B9  AND #$F0
  $C6BB  STA ram_btn_press,X

So once a Demo player reaches Y >= $C8, the original program removes A/B
from the *press* byte and the tank stops shooting near the HQ.

BCEX added held-B auto fire at $EF7D.  That helper combines:

  held B from $06,X
  OR
  normal press from $08,X

The Demo AI had already cleared $08,X, but $06,X still contained B because
the table values contained both A and B.  Therefore BCEX auto-fire restored
a fire command and defeated the original HQ-side no-shoot safeguard.

Runtime 6.9.2 correction
------------------------
Only the Demo AI table changes:

CPU $C6C2-$C6C5

Before:
  13 43 23 83

After:
  11 41 21 81

B is removed; A remains.

Result:
- normal Demo movement is unchanged;
- normal Demo shooting away from the HQ is unchanged because A still fires;
- at Y >= $C8 the original Demo code removes A from ram_btn_press;
- there is no held-B left for BCEX auto-fire to restore;
- Demo should stop firing into the base area as intended.

No QXR1 layout, Config v3 format, Web editor format, or Desktop editor
format changes are required.
